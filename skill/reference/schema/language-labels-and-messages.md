# GROUP 24: LANGUAGE, LABELS AND MESSAGES

Every string here is written by the method, and every one must be byte-identical
between two runs.

**THE HEADER SWEEP COVERS EVERY GRID AND NOT ONLY THE ENTITY SHEETS, AND IT IS
RECORDED HERE BECAUSE IT MISSED THE OTHERS ONCE.** The sweep that made every column
header a variable was run over the entity sheets, where it holds absolutely: every
header those sheets carry has a variable, so a literal there is always a second
source of truth for something already bound. It was not run over the REFERENCE
TABLES, which the output contract treats as grids in every respect a formatting
element cares about, and a summary sheet therefore shipped with about a dozen
columns whose headers were plain-language literals with nothing behind them. The
run disclosed them, correctly, as defaulted headers with no variable to read, which
is the outcome the contract provides for and is not a licence: **a header with no
variable is the defect this whole group exists to close**, it cannot be renamed into
an organization's own language, and it drifts between runs of two implementers. The
columns of the summary and the legend are below with the rest. A grid is a grid: if
a run writes a header onto it, a variable names that header.

TAXONOMY SHAPE, CLOSE_STATE_VOCABULARY. A KEYED SET with exactly NINE entries,
one per close-date state, looked up BY STATE KEY. Each entry carries:
- `key`: the state key, from the fixed set of nine below. Never renamed.
- `label`: the SHORT string written into the HDR_CLOSE_STATE cell. One fixed
  string, no placeholder, short enough that a reader can sort and scan the column
  by it.
- `row_wording`: the sentence written onto the row, which carries the date and any
  count, horizon date or carryover label the state needs.

**IT IS ONE TAXONOMY AND NOT TWO MAPPINGS, AND THE REASON IS THE HOLE IT CLOSES.**
The label and the wording are always looked up together, by the same key, at the
same moment. Two separate lists can be total individually and still leave a state
with a label and no sentence, or a sentence and no label, and neither list's own
count would show it. One entry per state makes that state unrepresentable.

**THE NINE STATE KEYS ARE FIXED VOCABULARY, NOT CONFIGURATION.** An organization
binds what each state is CALLED and how each row READS. It does not add, remove or
reorder the states, because the states partition the number line and the tests that
assign them are method rather than language: `due_this_plan`, `date_unreadable`,
`due_next_window`, `due_on_near_horizon`, `due_beyond_horizon`,
`due_before_plan_starts`, `passed_this_window`, `passed_earlier_window`,
`no_derivable_date`.

**WHY THE STATES ARE SEPARATE AT ALL, RECORDED HERE SO NOBODY MERGES THEM BACK.**
Four of them sit at the same floor weight and are four different facts about a
date. A run merged them once and labelled seventeen items EXPIRED that fell due
eight days AFTER the run date, before the planned window opened. The weight was
right and the word was false, and a reader holding a future date beside the word
EXPIRED concludes the report does not know what it is looking at. The weights are
not what this vocabulary governs; the truth of the sentence is.

TAXONOMY SHAPE, URGENCY_VOCABULARY. A KEYED SET with exactly FIVE entries, one per
urgency state, looked up BY STATE KEY. Each entry carries:
- `key`: the state key, from the fixed set of five below. Never renamed.
- `label`: the string written into the HDR_URGENCY cell. One fixed string, no
  placeholder, short enough to sort and scan a column by.

**THE FIVE STATE KEYS ARE FIXED VOCABULARY, NOT CONFIGURATION, AND THEY PARTITION
THE CASES RATHER THAN SAMPLING THEM:** `overdue`, `due_this_window`, `later`,
`passed_nothing_outstanding`, `no_date_on_file`. An organization binds what each
state is CALLED. It does not add, remove or reorder them.

**THE FIFTH STATE IS THE ONE THAT WAS MISSING, AND A CLOSED SET WITH A HOLE IN IT
IS WORSE THAN AN OPEN ONE.** The set shipped with four members and a rule that
`overdue` requires at least one outstanding item on the row, on the good ground
that a row with nothing outstanding must never be sent to somebody as late work. A
row whose date had passed and which carried nothing outstanding therefore had no
value it could lawfully take: `overdue` was forbidden by the rule, the two
window-relative values were false statements about the date, and the not-on-file
value was false because a date was on file. A run may not invent a member of a
closed set, so there was nothing correct to write. On one live run that was five
units out of a hundred and ninety, each of which had to be named in the legend by
hand. `passed_nothing_outstanding` is that row's true statement and it costs the
reader nothing: the date has passed and there is nothing on it to do.

**THE TOTALITY ARGUMENT, WHICH IS THE VALIDATION.** A unit either has a date this
run could resolve or it does not. Where it does not, `no_date_on_file`. Where it
does, the date falls inside the operating window, after it, or before it, which is
three cases and no fourth; and the before-it case splits on whether anything is
outstanding on the row, which is two cases and no third. Five leaves, every unit on
exactly one, and the urgency column never re-orders a sheet and never adds or
removes a row whichever leaf it lands on.

### Group 24: Language, labels and messages

Every header string in this group defaults to the plain English word for the
concept, and every default is byte-identical between runs so two reports remain
comparable. The shared notice for the header group is written once and printed
once, naming the count of defaulted headers rather than repeating a line per
column.

**A HEADER STRING WRITTEN INTO A SKILL'S OWN PROSE IS A SECOND SOURCE OF TRUTH AND
IS A DEFECT WHEREVER IT APPEARS.** A skill names the VARIABLE and the run resolves
it; a skill that writes the words the column should be headed with produces a third
name for a column that already has one, an organization that rebinds the header
finds the artifact unchanged, and nothing in the bundle updates the prose when the
default moves. Where a skill's prose and this appendix disagree about the letters
in a header, THIS APPENDIX GOVERNS and the prose is stale.
