# GROUP 16: FORMATTING

**THE PALETTE, THE BODY FACE AND THE TABLE STYLE ARE DEFERRED AND NOT OPTIONAL,
AND THE REASON IS A RULE THAT APPLIES TO THE WHOLE SCHEMA.** An earlier revision
marked TABLE_STYLE_NAME, the eight COLOR_ variables below, BODY_FONT,
BODY_FONT_SIZE, TITLE_FONT_SIZE and SECTION_FONT_SIZE as OPTIONAL. OPTIONAL means
"nothing degrades without it, and the run says nothing about it", and OPTIONAL
variables get no SECTION A1 row, so they have no documented default. But
reference/output-contract.md PART 2 makes the elements that READ them MANDATORY, verified
programmatically, with a failure blocking publication, and PART 7.1 records that
an element gate which cannot run has FAILED. On a first run at an unbound
organization there was therefore no fill, no face, no style and no border colour;
five elements had nothing to apply and nothing to verify; and the run could not
publish anything at all, on colour alone.

**THE GENERAL RULE, STATED HERE BECAUSE THIS IS WHERE IT WAS BROKEN: ANY VARIABLE
THAT A MANDATORY, PUBLICATION-BLOCKING GATE READS MUST BE DEFERRED OR CONDITIONAL
AND MUST CARRY A DOCUMENTED DEFAULT.** OPTIONAL is for a variable whose absence
leaves a correct artifact that is merely less rich. A variable whose absence stops
an artifact existing is not optional in any sense of the word, whatever the table
says. Before marking anything OPTIONAL, check whether a mandatory element, a hard
gate or a verification step names it; if one does, it is DEFERRED and it gets an
A1 row.

**WHAT STAYS OPTIONAL HERE, AND WHY.** The four ROW_HEIGHT_ minimums and
NARRATIVE_COLUMN_WIDTH_RANGE stay OPTIONAL, because no element reads them: elements
12 and 14 require every row height to be COMPUTED from wrapped content and forbid a
fixed number, so those variables can only ever raise a computed floor and their
absence changes nothing a gate looks at.

**THE PALETTE SEPARATION RULE, STATED ONCE HERE AND CITED FROM EVERY FILL VARIABLE
THAT IT GOVERNS.** The seven fills a scored grid can carry are COLOR_STATUS_PASS,
COLOR_STATUS_GAP, COLOR_STATUS_UNASSESSABLE, COLOR_STATUS_NOT_SCORED,
COLOR_STATUS_RETIRED, COLOR_ALERT_WARN and COLOR_ALERT_OVERDUE, **AND THE RULE RUNS
OVER THE UNION OF THOSE SEVEN AND EVERY VALUE BOUND IN CLASSIFICATION_FILLS**, because a reader meets
them all on one grid: a classification fill separated from the other classification
fills but not from the alert bands is one fill on a photocopy exactly as any other
collision is, and a rule whose domain stops short of the newest fill catches
nothing about it. Every one of them must be distinguishable
from every other **IN GREYSCALE AS WELL AS IN COLOUR**, and the greyscale half is
the operative half, because these workbooks are printed, photocopied and read by
people who do not see the hues apart. Two pale fills of different hue at the same
lightness are ONE fill on a photocopy, and the state they encode is gone.

**THE TEST, AND IT IS ARITHMETIC RATHER THAN AN OPINION.** Compute each fill's
greyscale value as 0.299 times red plus 0.587 times green plus 0.114 times blue, on
the 0 to 255 scale. **No two members of that union may sit within 8 of each
other.** Run it
whenever a fill is bound or a default is changed; it is four lines of script and it
has already caught one collision in this file's own defaults, where the approaching
band and the not-scored fill were 0.4 apart and therefore identical on paper.

**AND COLOUR IS NEVER THE ONLY CHANNEL.** Every scored cell carries its state as
TEXT under CLASSIFICATION_LABELS, so the grid reads correctly with no palette at
all. The separation rule is what keeps the second channel honest; it is not what
makes the grid readable.

**WHAT THE SEPARATION RULE'S UNION DOES NOT CONTAIN, SAID HERE SO NOBODY ADDS IT.**
COLOR_TITLE_BAND, COLOR_SUBTITLE_BAND, COLOR_SECTION_HEADER and COLOR_LABEL_FILL are
STRUCTURAL BANDS, not state fills. They encode nothing about a unit, they stand in
positions a reader cannot mistake for a data cell, and no reader ever compares a header
band against a scored cell to decide what a cell means. Their readability requirement is
the CONTRAST test of the output contract rather than this SEPARATION test, and it is a
harder test than this one. **They are still held 8 apart FROM EACH OTHER and from the
sheet ground under this same arithmetic**, so the panel hierarchy of title, sub-band,
section header and label survives a photocopy; that is the whole of their relationship to
this rule.

**THE OPACITY RULE, STATED ONCE HERE AND BINDING ON EVERY COLOUR VARIABLE IN THIS
GROUP.** A colour is written with an EXPLICIT OPAQUE ALPHA. Where the container's colour
field takes eight hex digits, alpha first, the value is written `FFRRGGBB` and the alpha
byte is literally `FF`. Where it takes six, the value is six digits and is never padded
to eight. **AN ALPHA BYTE OF `00` IS FORBIDDEN AND BLOCKS PUBLICATION.** The reason is
measured rather than theoretical: three delivered workbooks wrote every header fill as
`001F3864` and every header font colour as `00FFFFFF`. The common spreadsheet engine
treats `00RRGGBB` as fully OPAQUE, so those files were correct in the tool that built
them; many other renderers, web previewers and conversion pipelines among them, honour
`00` as FULLY TRANSPARENT, so in those the fill vanished and bold white header text
landed on a white ground. **A colour that renders correctly in the tool the author built
it in and invisibly in the tool the reader opens it in is a publication-blocking failure,
not a cosmetic one**, because the run that made it verified a readable artifact and
shipped an unreadable one. The full form and its verification live in the output
contract; what lives here is the requirement on the VARIABLE, so the value is right at
its one binding site and not only at the cell.

**THE CONTRAST REQUIREMENT ON A BAND AND ITS TEXT, WHICH IS NOT THIS GROUP'S TO STATE
AND IS NAMED HERE SO NO BINDING MISSES IT.** reference/output-contract.md PART 2.8 holds the
arithmetic and the two floors, and it runs THREE assertions on every band-and-text pair:
the intended pair, the pair as it renders when the FILL fails to render, and the pair as
it renders when the FONT COLOUR fails to render. **A DARK BAND UNDER LIGHT TEXT CANNOT
PASS ALL THREE**, so COLOR_TITLE_BAND and every other structural band is bound LIGHT and
COLOR_HEADER_TEXT is bound DARK. Binding a band dark, or its text light, produces a
workbook that cannot publish.

TAXONOMY SHAPE, CLASSIFICATION_VOCABULARY. The closed set of STATES that a declared
classification column's fills are keyed on. Each entry carries:
- `key`: the stable state id, never renamed, because a shaded grid is compared
  across periods and a renamed state silently breaks that comparison.
- `meaning`: one line, in the business's own words, published in the legend beside
  the fill, so a reader can see the whole set of answers the column can give.
- `leading_token`: the form in which the state appears at the front of a cell value
  that carries more than the state alone. Where the cell value IS the state, this is
  the key itself.

The SET as a whole carries one `resolution_rule`: a DECLARED, TOTAL and MECHANICAL
statement resolving every populated cell to EXACTLY ONE key, none to two and none to
none, published beside the vocabulary.

**THE STATE SET IS NOT THE SET OF DISTINCT CELL VALUES, AND THAT DISTINCTION IS THE
WHOLE REASON THE FILL IS REACHABLE ON A REAL GRID.** A cell value is routinely a
state crossed with a reason code, a qualifier or a finding, so the distinct values a
census column holds run into the hundreds while the states behind them stay at five.
The hundreds are values; the five are the vocabulary. A binding that enumerates the
values instead of the states produces a set nothing can be a member of, a map with
hundreds of colours in it, and a legend nobody reads.

**HOW IT RELATES TO CLASSIFICATION_LABELS, STATED SO NOBODY BINDS BOTH TO THE SAME
THING TWICE.** CLASSIFICATION_LABELS is the scored-cell instance of this idea: five
states with a symbol, a scored flag, a pass flag and a fill variable each, owned by
Group 18 because it also decides what counts in a denominator. CLASSIFICATION_VOCABULARY
is the general case a classification column under the output contract keys its fills
on, and it decides nothing about scoring. Where a column's states ARE the label keys,
this vocabulary is bound to those keys and the two agree by construction; where a
column classifies something the scorecard never scores, this is the only one of the
two that applies.
