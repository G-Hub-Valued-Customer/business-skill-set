# THE DOCTRINE, AND HOW AN SD- IDENTIFIER RESOLVES

# SHARED DOCTRINE

The rules that apply across more than one of the three skills, plus every rule
that is universal regardless of skill.

Skills: PLANNING (periodic population planning and ranked action lists), REVIEW
(objective setting, progress tracking and performance write-ups), SCORECARD
(compliance and execution gap scoring).

## How to read an entry

- **ID**: stable. Never renumbered, never reused. Skills cite these IDs.
- **Rule**: the operative statement. Where precision lives in the phrasing, the
  original wording is preserved and only employer literals are replaced.
- **Mechanism**: the formula, threshold, or procedure, where one exists.
- **Prevents**: the failure the rule exists to stop.
- **General form**: the rule restated in bound variables. Where the original was
  written in terms of stores, categories or operating companies, the original
  survives underneath as a worked example.
- **Source**: P-Dn is rule n of the planning doctrine inventory; R-Dn is rule n
  of the review doctrine inventory. Two sources means the two skills stated the
  same rule independently, which is the strongest evidence it is doctrine.
- **Applies**: which of the three skills the rule binds.

## The five rules that govern the other rules

- **G1. One declared contract per deliverable, superior to every other section.**
  Any later instruction that disagrees with the contract is the defect.
- **G2. Fail closed. Unknown is not pass.**
- **G3. Never default an unknown to the value that maximizes its score.**
- **G4. Every number carries a second number the writer did not choose.**
- **G5. A rule that costs nothing when it does not fire and keeps the method
  portable is worth carrying.**

## THE RESOLUTION RULE

An identifier of the form `SD-XXX-nn` resolves to `reference/doctrine/XXX.md`.
The three letters ARE the file name. There is no search, no index lookup and
no ambiguity: read that one file and the rule is in it, under a heading that
is the identifier itself.
